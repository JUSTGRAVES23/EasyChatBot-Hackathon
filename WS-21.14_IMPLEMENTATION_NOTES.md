# WS-21.14 — Real Backend Wiring

## Objective

Replace the legacy Operations Center Beta dashboard stub with the real
WS-21 operational dashboard application services.

## Architecture

ProductionHealthConfiguration
→ ProductionReadinessService
→ OperationalHealthSnapshotService
→ OperationalDashboardService
→ OperationsCenterDashboardFacade
→ OperationsCenterDashboardAPI

OperationalEventService is owned by `OperationsCenterComposition` and is
created once per composition instance so incident/event state is not reset
for every dashboard request.

## Important

The HTTP router must retain the composition instance for application
lifetime. Do not call `create_operations_center_dashboard_api()` for every
request.

The router should call:

```python
payload = await dashboard_api.get_dashboard()
```

Do not use `asyncio.run()`.

## Real dependency behavior

`ProductionHealthConfiguration()` intentionally uses the existing
infrastructure health checks:

- PostgreSQLHealthCheck
- LLMProviderHealthCheck
- TelegramHealthCheck

Those checks already use the project's existing environment/configuration
and infrastructure factories.

## Security

The dashboard consumes `OperationalDashboardSnapshot.as_dict()` only.
Learner message content, prompts, responses, credentials and secrets must
not enter the dashboard contract.

## Verification

Run the focused WS-21.14 test first, then the complete health suite and
frontend TypeScript/build checks after the HTTP router is wired.
