# WS-22.3.1 — Publication Execution Domain/Application Contract

## Scope

Provider/channel-independent execution contracts only.

### Included

- `PublicationExecutionRequest`
- `PublicationExecutionResult`
- `PublicationExecutionStatus`
- `AnnouncementPublisher` protocol
- `PublicationExecutionService`
- in-process idempotency contract
- success/failure lifecycle handling
- audit boundary
- unit/integration-style contract tests

### Explicitly excluded

- Telegram implementation
- external provider calls
- frontend publishing UI
- new repositories
- production side effects

## Architecture

```text
Approved Publication
        |
        v
PublicationExecutionService
        |
        v
AnnouncementPublisher (Protocol)
        |
        v
Infrastructure adapter (future WS-22.3.3)
        |
        v
Execution Result
        |
        +--> Publication lifecycle
        |
        +--> Audit boundary
```

## Security

Execution audit receives stable operational identifiers and error codes.
Provider exception text is not copied into audit events.

## Idempotency

The current WS-22.3.1 contract uses an in-process idempotency map. This is
deliberately an application contract and is not yet a distributed persistence
mechanism. A durable/distributed idempotency repository belongs in a later
execution-hardening slice before multi-worker production deployment.
