APPROVED SECURITY PRINCIPLES
----------------------------

1. Transaction authorization is distinct from authentication.

2. Transaction authorization is distinct from authentication assurance.

3. Transaction authorization is distinct from business authorization.

4. Authentication Assurance is supplied by W15.6.

5. W15.7 consumes W15.6 assurance where transaction policy requires it.

6. W15.7 MUST NOT implement MFA.

7. W15.7 MUST NOT create artificial A2/A3 assurance.

8. A3 authentication does NOT automatically authorize a transaction.

9. Transaction authorization MUST bind the exact transaction.

10. Principal binding is mandatory.

11. transaction_id binding is mandatory.

12. operation binding is mandatory.

13. amount binding is mandatory where applicable.

14. currency binding is mandatory where applicable.

15. merchant/service/recipient binding is mandatory where applicable.

16. relevant risk context MUST be bound according to policy.

17. Transaction representations MUST be deterministic and canonical.

18. Monetary authorization MUST NOT depend on binary floating-point equality.

19. Nonce uniqueness MUST be enforced at the trusted application boundary.

20. Authorization identifiers MUST distinguish authorization instances
    from business transaction identifiers where appropriate.

21. Authorization MUST be single-use.

22. Authorization consumption MUST be atomic.

23. Concurrent consumers MUST NOT both succeed.

24. Replay MUST fail closed.

25. Expired authorization MUST fail closed.

26. Revoked authorization MUST fail closed.

27. Invalid lifecycle transitions MUST fail closed.

28. Caller-controlled approval assertions MUST NOT create trusted
    transaction authorization.

29. Approval MUST remain bound to the exact transaction presented.

30. Trusted server/application time MUST determine expiry and validity.

31. Caller-controlled current time MUST NOT determine validity.

32. Material risk changes MUST invalidate or require fresh authorization
    according to central policy.

33. Transaction authorization MUST NOT bypass AuthorizationService.

34. Business services MUST NOT implement transaction authorization policy.

35. Business services MUST NOT implement their own MFA.

36. Transaction authorization policy MUST be centrally supplied.

37. Exact monetary thresholds MUST be centrally governed.

38. Audit evidence MUST correlate the authorization and transaction.

39. Raw credentials and security secrets MUST NOT be stored in audit
    evidence.

40. Cryptographic transaction signing MUST NOT be claimed until actual
    cryptographic protection is implemented and tested.

41. ZITADEL and Keycloak remain outside this implementation boundary.

42. Existing AuthenticationService remains unchanged.

43. Existing Principal remains unchanged.

44. Existing IdentityProvider remains unchanged.

45. Existing SessionIdentityProvider remains unchanged.

46. Existing AuthorizationService remains unchanged unless a separately
    reviewed architectural necessity is demonstrated.
