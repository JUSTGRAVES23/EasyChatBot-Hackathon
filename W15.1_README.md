# EasyChatBot W15.1 — Developer Admin UoW Lifecycle Hardening

## Engineering objective

Replace the production-shared mutable Developer Admin Unit of Work with a
per-operation UoW factory.

## Current risk

`DeveloperAdminService` currently receives a concrete UoW instance. Production
composition creates one `PostgreSQLDeveloperAdminUnitOfWork` and stores that
instance in the service. The UoW owns mutable session/transaction state.

That object must not be shared across concurrent requests.

## Target architecture

Request -> DeveloperAdminService -> UoW Factory -> fresh PostgreSQL UoW
-> fresh SQLAlchemy session -> one transaction -> role mutation + audit
-> commit/rollback.

The service may remain application-scoped because it must not retain
request-scoped transaction state.

## Required implementation

1. Add an application-level `DeveloperAdminUnitOfWorkFactory` contract.
2. Change `DeveloperAdminService` production construction to receive the factory.
3. For every grant/revoke operation, call the factory exactly once and use the
   returned UoW as the operation's transaction boundary.
4. Preserve the existing atomic role + audit transaction semantics.
5. Ensure the transaction-aware audit repository is bound to the fresh UoW/session
   and never commits or rolls back independently.
6. Change `main.py` composition from a singleton UoW to a factory.
7. Keep API authentication, authorization, Principal propagation, last-admin
   protection, idempotency, and production migration controls unchanged.
8. Do not add an Alembic migration for this lifecycle-only change.

## Important implementation constraint

Do NOT solve this by wrapping the existing singleton UoW in a callable.
The callable must construct a new UoW, with fresh transaction/session state and
transaction-bound audit repository state for each operation.

## Tests required

- factory returns distinct UoW instances;
- service creates a fresh UoW for each mutation;
- successful grant commits role + audit;
- successful revoke commits role + audit;
- audit failure rolls role mutation back;
- role failure creates no committed audit event;
- last Developer Admin remains protected;
- duplicate grant is idempotent and produces no false audit;
- actor Principal reaches the audit event;
- concurrent operations do not share UoW/session state;
- existing Developer Admin tests remain green;
- full backend regression remains green.

## Definition of Done

Architecture reviewed, implementation integrated, targeted tests green, full backend
regression green, security review complete, startup/import verification complete,
no migration changes, and 4-eyes review/sign-off complete.
