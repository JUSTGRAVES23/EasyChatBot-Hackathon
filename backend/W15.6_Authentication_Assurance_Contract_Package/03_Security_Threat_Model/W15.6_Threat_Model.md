# W15.6 Threat Model

## Primary threats

T1 — Assurance downgrade
Attacker converts A2/A3 requirement into A0.

Control:
- central policy evaluation
- immutable/effectively immutable requirement
- explicit denial on insufficient assurance

T2 — Stolen/old step-up evidence
Attacker reuses previous authentication evidence.

Control:
- freshness
- session binding
- evidence identifiers
- later transaction nonce/binding

T3 — Principal substitution
Attacker presents valid evidence for another user.

Control:
- bind validated identity subject to application principal
- reject mismatched subject/principal

T4 — Forged provider claims
Attacker injects arbitrary authentication claims.

Control:
- OIDC token validation in Identity Adapter
- issuer/audience/signature/expiry validation
- controlled claim mapping

T5 — MFA implementation drift
Different business services enforce different MFA rules.

Control:
- central Authentication Assurance Service
- service-level assurance requirement only

T6 — Confusing authentication with transaction approval
Valid login is treated as approval for a financial transaction.

Control:
- separate Transaction Authorization boundary
- exact transaction binding at W15.7+

T7 — Sensitive assurance data leakage
Authentication evidence enters logs or telemetry.

Control:
- structured redaction
- no secrets/tokens/OTP/WebAuthn private material
- security event correlation IDs only

T8 — Replay
Attacker reuses valid step-up or transaction evidence.

Control:
- short freshness
- single-use transaction authorization
- nonce and operation binding
