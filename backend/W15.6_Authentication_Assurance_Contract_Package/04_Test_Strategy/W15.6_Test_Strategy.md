# W15.6 Test Strategy

No production test should be added until the contract receives review approval.

## Contract tests to implement after approval

1. A0 accepts valid authenticated principal.
2. A1 rejects unauthenticated principal.
3. A1 rejects stale authentication.
4. A1 rejects insufficient authentication strength where policy requires MFA.
5. A2 rejects A0 context.
6. A2 accepts valid recent step-up.
7. A3 rejects password-only authentication.
8. A3 requires phishing-resistant authentication.
9. A3 requires user verification.
10. Assurance cannot be downgraded by request input.
11. Mismatched provider subject and principal are rejected.
12. Expired assurance evidence is rejected.
13. Provider-specific claims are normalized through the adapter.
14. Raw tokens/secrets are absent from logs.
15. Failure codes distinguish assurance failure from authorization failure.
16. Policy version is carried in audit evidence.

## Security regression gate

Relevant tests must be green before W15.6 can advance.

If any relevant test fails:
STOP → diagnose → fix → test → review → verify.

Never commit a failing W15 security workstream.
