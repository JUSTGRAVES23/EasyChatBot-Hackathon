# P1.2.4 Canonical ProviderResult / Usage Contract

## Objective

Introduce a provider-independent execution result on the **live Beta
Telegram provider path** without changing the Telegram-facing
`ConversationRuntime.respond(...) -> str` contract.

## Canonical boundary

```text
Provider SDK
    ↓
Provider adapter
    ↓
ProviderResult
    ├── provider_id
    ├── model
    ├── content
    ├── usage
    │    ├── input_tokens
    │    ├── output_tokens
    │    └── total_tokens
    ├── provider_request_id
    ├── latency_ms
    └── diagnostics
         ↓
ConversationRuntime
    ↓
Telegram/application response (str)
```

## Rules

1. Provider SDK objects never cross the provider boundary.
2. Token values are nullable; providers must not invent unavailable data.
3. `provider_request_id` is nullable because local Ollama execution does
   not necessarily expose one.
4. Cost is intentionally **not** calculated in `ProviderResult`.
   Cost calculation remains the responsibility of the usage/cost layer.
5. The Operations Center remains a consumer of usage data, not the
   accounting engine.
6. `content` is canonical; `output` remains a read-only compatibility alias.
7. The runtime keeps returning `str` to existing Telegram callers.
8. Existing test doubles returning strings remain supported during the
   migration.

## Deliberately deferred

- durable usage ledger wiring
- automatic cost calculation
- capability/functionality attribution
- provider-specific pricing
- user/agent attribution
- persistence schema changes

These belong to the next vertical slice after the contract is proven.

## Acceptance criteria

- [ ] ProviderResult is immutable and provider-independent.
- [ ] OpenAI normalizes request ID, model, latency and token usage.
- [ ] Ollama normalizes model, latency and token usage when available.
- [ ] Missing provider metadata remains `None`.
- [ ] Telegram runtime still returns a string.
- [ ] Existing string-returning test doubles continue to work.
- [ ] No provider SDK response object crosses the boundary.
- [ ] No cost logic is placed in provider adapters.
