# P1.5.4 — Provider to Durable Usage Ledger E2E

## Objective

Prove the complete provider-result-to-durable-ledger path using a deterministic
fake provider and the real PostgreSQL usage repository.

## Test boundary

`FakeProvider -> ProviderResult -> ConversationRuntime -> ProviderUsageCapture -> ProviderUsageService -> PostgreSQLProviderUsageRepository -> provider_usage_events`

The test does not call an external LLM provider and does not require provider
credentials.

## Migration boundary

The test does not create or modify database schema. If
`provider_usage_events` does not exist, the test skips and reports that the
shared database migration remains Academy-owned.

## Acceptance criteria

- A successful canonical `ProviderResult` reaches `ConversationRuntime`.
- Usage capture creates the usage event with attribution and provider metrics.
- The real PostgreSQL repository persists the event.
- The persisted row contains the expected provider, model, attribution,
  token counts, latency, cost, quality and success status.
- No production provider is called.
- No migration is executed by the test.
