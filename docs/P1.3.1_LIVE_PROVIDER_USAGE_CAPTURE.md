# P1.3.1 — Live Provider Usage Capture Integration

## Objective
Connect the live Beta Telegram provider execution path to the existing
Provider Usage capture boundary without changing TelegramConversationService.

## Flow
Provider Adapter -> ProviderResult -> ConversationRuntime ->
ProviderUsageCapture -> ProviderUsageEvent -> ProviderUsageService ->
existing repository.

## Scope
- Composition-boundary integration only.
- Preserve ConversationRuntime.respond(...) -> str.
- Capture successful and failed provider results.
- No Telegram service changes.
- No legacy backend/providers path changes.
- No Operations Center changes.
- No durable-ledger claim.

## Accounting limitation
The current ProviderUsageEvent/repository is an in-memory legacy accounting
boundary. Cost remains explicitly supplied by the capture context and is
therefore zero unless a later cost-calculation step supplies it.
provider_request_id remains on ProviderResult and is not silently discarded
into an unrelated field.

## Review gate
This package is ready to test, not ready to declare the Usage Ledger complete.
