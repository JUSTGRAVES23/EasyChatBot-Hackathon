# M7.2 Backend Integration — READY v1.0

## Scope

This package wires the existing canonical ProcessingActivity /
ProcessingRegistry capability to the M7.2 Screening Workspace and invokes the
existing M3 ScreeningService.

## Flow

M7.2 frontend
-> GET /api/privacy/screening/processing-activities
-> canonical application/privacy ProcessingRegistry
-> POST /api/privacy/screening/screen { processing_id }
-> ProcessingActivityScreeningAdapter
-> existing ScreeningService
-> ScreeningResult

## Security / governance

The browser supplies only processing_id. Screening criteria and legal
materiality are server-derived. Missing legally material information fails
closed as LEGAL_REVIEW_REQUIRED.

validate.py remains a validation fixture and is not imported by the runtime.

No second ProcessingActivity model or registry is introduced.

## Current persistence limitation

The repository currently has no identified durable canonical privacy Processing
Activity store in the runtime composition. This package therefore composes the
existing deterministic ProcessingRegistry for Beta 1 without introducing a
new database schema in M7.2.

Before final production approval, the canonical registry should be placed
behind the approved durable repository boundary and undergo DPO/GRC review.
