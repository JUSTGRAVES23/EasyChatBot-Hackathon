# WS-21.14 — Backend Wiring Contract

## Required backend response

The endpoint used by the dashboard should provide sanitized operational information for:

- overall health
- PostgreSQL health
- LLM provider health
- Telegram health
- Private Classroom metrics
- Announcement Group metrics
- operational incidents
- correlation IDs
- authorized controlled user references
- World association
- operational timeline

## Field rule

Every field consumed by the frontend must be backed by a verified backend contract.

If a field is unavailable:

```text
MISSING -> backend contract change
```

not:

```text
MISSING -> frontend invented default
```

## Security contract

The backend response must never contain:

- learner message content
- prompts
- model responses
- passwords
- API keys
- Telegram bot tokens
- database connection strings
- provider credentials
- unrestricted raw Telegram identity

## User identity

When an operational incident needs identity investigation, the backend may expose only the controlled operational user reference permitted by the authorization boundary.

## Error contract

The API must return a safe operational error response.

Internal exception text, stack traces and dependency credentials must not reach the browser.

## Read-only contract

The dashboard endpoint is observational.

It must not:

- execute an LLM
- publish Telegram messages
- modify PostgreSQL
- change provider routing
- change Runtime policy
- remediate an incident
