# WS-21.13 — UX Validation

## Primary operator question

The dashboard must answer, within seconds:

> Is EasyChatBot operational, where is the problem, and what should I investigate?

## Visual hierarchy

### Tier 1 — System health

- Overall health ring
- PostgreSQL
- LLM
- Telegram

### Tier 2 — Operational surfaces

- Private Classroom
- Announcement Group

These must remain visually distinct.

### Tier 3 — Investigation

- Incident severity
- Correlation ID
- Controlled user reference
- World
- Timestamp/outcome

### Tier 4 — Existing Operations Center

Existing:

- providers
- models
- agents
- escalations
- quality
- governance
- reports
- recommendations
- settings

must remain accessible.

## State design

Every operational panel must support:

- Loading
- Healthy
- Degraded
- Unhealthy
- Backend unavailable
- Empty/no incidents
- Unauthorized data

Internal exceptions must never be rendered directly.

## Responsive requirements

### Desktop

Use the full multi-column operational layout.

### Tablet

Collapse cards while preserving system health and incidents above the fold.

### Mobile

Prioritize:

1. Overall health
2. Dependency health
3. Critical incidents
4. Private Classroom / Announcement Group status

Detailed investigation remains available through drill-down.

## Accessibility

- semantic headings
- readable contrast
- status must not rely on color alone
- keyboard-accessible interactive elements
- useful aria labels for health indicators
