# WS-21.13 — Data Contract Matrix

Every visual field must have a verified source.

| Dashboard field | Required source | Validation |
|---|---|---|
| Overall health | Operational health/snapshot service | Verify |
| PostgreSQL status | Real dependency health result | Verify |
| LLM status | Real dependency health result | Verify |
| Telegram status | Real dependency health result | Verify |
| Classroom messages | Private Classroom operational metrics | Verify |
| Message failures | Operational event/metrics contract | Verify |
| Rate-limit events | Operational event/metrics contract | Verify |
| Abuse events | Operational event/metrics contract | Verify |
| Announcement scheduled | Announcement operational metrics | Verify |
| Announcement delivered | Announcement operational metrics | Verify |
| Announcement failures | Announcement operational metrics | Verify |
| Pending approval | Approved notification contract | Verify |
| Incidents | Operational incident service | Verify |
| Correlation ID | Operational event/incident contract | Verify |
| User reference | Controlled/authorized operational reference | Verify |
| World | World association in operational event/incident | Verify |
| Timeline | Operational event service | Verify |

## Rule

If a required field does not exist in the backend contract:

1. Mark it `MISSING`.
2. Do not invent a frontend value.
3. Do not use mock production data.
4. Record the backend contract gap.
5. Resolve the gap before WS-21.14 production wiring.

## Sanitization

The contract must never expose:

- learner message content
- prompts
- model responses
- passwords
- API keys
- bot tokens
- database URLs
- provider credentials
- unrestricted Telegram identity
