# WS-21.12 — Real Operations Center Integration

## Objective

Connect the existing `/operations-center` frontend to the canonical Operations Center backend contract and the WS-21 operational health/event/incident services.

This slice integrates real operational data without creating a second dashboard, route, port, API namespace, or runtime.

## Acceptance Criteria

1. `/operations-center` loads the real backend data.
2. Overall health ring uses the real operational health result.
3. PostgreSQL status is real.
4. LLM status is real.
5. Telegram status is real.
6. Private Classroom metrics are real.
7. Announcement Group metrics remain separate.
8. Incidents come from the operational incident service.
9. Correlation IDs are displayed for investigation.
10. Controlled user references can be displayed when authorized.
11. World association is displayed.
12. No learner message content reaches the dashboard.
13. No secrets reach the dashboard.
14. Loading/error states are handled cleanly.
15. Backend unavailable → safe dashboard error state.
16. Existing Operations Center functionality remains intact.
17. Frontend TypeScript/build passes.
18. WS-21 health/operations tests remain green.
19. Desktop layout works.
20. Tablet/mobile layouts work.

## Architecture

```text
Browser
  |
  v
Next.js /operations-center
  |
  v
Existing operationsCenter.ts API client
  |
  v
FastAPI /api/operations-center/*
  |
  v
Operations Center application services
  |
  +--> WS-21 operational health
  +--> WS-21 operational events
  +--> WS-21 operational incidents
  +--> controlled operational snapshot
  |
  v
Infrastructure health probes
  +--> PostgreSQL
  +--> LLM provider
  +--> Telegram
```

## Security boundary

The frontend must consume sanitized operational data only.

Never expose:

- learner message content
- prompts
- model responses
- passwords
- API keys
- Telegram bot tokens
- database URLs
- provider credentials
- unrestricted raw Telegram identity

User investigation must use an authorized controlled user reference.

## Surface separation

Private Classroom and Announcement Group remain distinct operational surfaces.

Private Classroom:

- dependency health
- message failures
- rate-limit events
- abuse events
- controlled user reference
- World
- correlation ID

Announcement Group:

- dependency health
- scheduled notifications
- delivery
- failures
- approval state
- correlation ID

## Definition of Done

All 20 acceptance criteria pass.

Additionally:

- no duplicate Operations Center route is introduced
- no duplicate Operations Center API namespace is introduced
- existing Operations Center navigation remains intact
- frontend build/type-check succeeds
- backend tests succeed
- relevant WS-21 tests succeed
- a real backend failure produces a safe UI state
- desktop/tablet/mobile rendering is verified
