# WS-21.14 — Real Backend Wiring

## Objective

Connect the existing `/operations-center` frontend to the verified backend operational dashboard contract.

WS-21.14 is the first production-data wiring slice after WS-21.13 UX and contract validation.

## Architectural boundary

```text
Browser
  |
  v
/operations-center
  |
  v
existing operationsCenter API client
  |
  v
FastAPI Operations Center router
  |
  v
application Operations Center dashboard service
  |
  +--> operational health
  +--> operational events
  +--> operational incidents
  +--> controlled operational snapshot
  |
  v
dependency probes / repositories
```

The browser must never access PostgreSQL, Telegram, LLM providers, or infrastructure credentials directly.

## Implementation rules

1. Reuse the existing Operations Center route.
2. Reuse the existing API client.
3. Reuse the existing backend router/application services.
4. Do not create a second dashboard.
5. Do not create a second API namespace.
6. Do not duplicate health logic in React.
7. Do not use mock production health data.
8. Do not expose raw exceptions.
9. Do not expose secrets or learner content.
10. Preserve Private Classroom / Announcement Group separation.
11. Preserve controlled identity references and correlation IDs.
12. Preserve existing Operations Center capabilities.

## Integration sequence

### Step 1

Confirm WS-21.13 contract findings are resolved.

### Step 2

Confirm the backend endpoint returns a sanitized operational snapshot.

### Step 3

Map the response into the existing frontend dashboard view model.

### Step 4

Replace only placeholder/mock dashboard values that correspond to verified backend fields.

### Step 5

Implement loading, degraded, empty, unauthorized and backend-unavailable states.

### Step 6

Run frontend type-check and build.

### Step 7

Run backend WS-21 health/operations tests.

### Step 8

Run Operations Center integration tests.

### Step 9

Verify desktop, tablet and mobile.

## Rollback

If the real backend contract is incompatible:

- stop
- restore the previous working dashboard behavior
- document the contract mismatch
- do not invent frontend fields
- do not bypass the application layer
