# WS-21.13 — Operations Center UX + Contract Validation

## Purpose

Validate the existing Operations Center UI against the existing backend contract before WS-21.14 real production wiring.

This workstream is intentionally non-invasive.

It must not:
- create a second dashboard
- create another `/operations-center` route
- create another API namespace
- call PostgreSQL, Telegram, or LLM providers from the browser
- activate WS-21.12 production integration
- delete existing implementations

## Validation flow

```text
Existing API response
        |
        v
Contract validation
        |
        +---- invalid/missing field ---> validation finding
        |
        v
Explicit UI view model
        |
        v
WS-21.11 visual components
```

## Required validation areas

1. Overall health
2. PostgreSQL
3. LLM
4. Telegram
5. Private Classroom metrics
6. Announcement Group metrics
7. Operational incidents
8. Correlation IDs
9. Controlled user references
10. World association
11. Operational timeline
12. Loading state
13. Degraded state
14. Backend unavailable state
15. Sanitization
16. Responsive layout
