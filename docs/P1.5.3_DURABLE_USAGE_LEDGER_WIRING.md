# P1.5.3 — Durable Usage Ledger Wiring

## Objective

Wire the existing PostgreSQL provider-usage repository into the production
Beta Telegram composition without changing the provider/runtime contract.

## Boundary

Production composition creates:

`session_factory -> PostgreSQLProviderUsageRepository -> ProviderUsageService -> ProviderUsageCapture -> ConversationRuntime`

The Operations Center remains a consumer of usage intelligence and does not
become the accounting engine.

## Compatibility

- Existing `ProviderUsageRepository` abstraction is preserved.
- In-memory repository remains available for tests/default application
  composition where no repository is supplied.
- Existing runtime injection seams are preserved.
- No Alembic migration is included.
- The authoritative shared-database migration remains governed by the
  P1.4.5 migration handoff.

## Acceptance

1. Production composition constructs `PostgreSQLProviderUsageRepository`.
2. That repository is passed through the existing repository abstraction.
3. `ProviderUsageService` and `ProviderUsageCapture` use the injected repository.
4. Existing injected runtime/capture tests remain compatible.
5. No provider adapter or Operations Center boundary is changed.
