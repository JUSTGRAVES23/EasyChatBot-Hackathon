# P1.4.2 — Durable Provider Usage Ledger Migration

## Status

Migration artifact prepared and schema contract tested.

**Database execution is intentionally NOT part of this package.**

## Why the migration is isolated

The target PostgreSQL database currently contains Alembic revisions that
are not present in this repository:

- `20260901_cmp_monitoring_plan_items`
- `20260902_m2_3_world_catalogue`
- `20260903_m4_2_r4_user_role`

The repository's current head is `ACADEMY_NOTIFICATION_DELIVERY`.

Therefore this migration is created as an explicit independent branch
(`provider_usage_ledger`) rather than pretending it belongs to the broken
current linear chain.

Do not run `alembic upgrade head` or stamp this revision until migration
ownership/graph reconciliation has been explicitly approved.

## Schema

Table: `provider_usage_events`

Fields:

- id
- provider
- model
- capability
- functionality
- agent
- input_tokens
- output_tokens
- latency_ms
- estimated_cost NUMERIC(18,8)
- quality_score NUMERIC(5,2)
- success
- created_at TIMESTAMP WITH TIME ZONE

Operational indexes are created for provider, model, capability,
functionality, agent, success and created_at.

## Boundary

This migration supports:

`ProviderUsageEvent -> PostgreSQLProviderUsageRepository -> durable ledger`

It does not change:

- provider adapters;
- provider result contracts;
- usage capture;
- Operations Center;
- Telegram;
- pricing/cost calculation;
- migration state reconciliation.
